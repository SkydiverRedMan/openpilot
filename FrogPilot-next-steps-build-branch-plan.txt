Native UI recommendation
------------------------
Do not try to make the native Navigation Assist button show up again yet.

What happened:

- The C++ source file on the comma did contain the new button.
- The running binary `selfdrive/ui/ui` did not contain the button.
- We rebuilt `selfdrive/ui/ui` directly on the comma from the source tree.
- The rebuilt binary was ARM64 and did contain the new button text.
- After installing that binary into the prebuilt branch, the comma reached the
  boot logo but the UI did not stay up.
- We tried Wayland/Qt environment fixes and a manager native-process launch
  workaround.
- The UI still crash-looped.
- We rolled back to the old working prebuilt UI binary.

Conclusion:

Do not copy a single rebuilt native UI binary into the prebuilt branch unless
we know it was built from the exact matching release tree and all matching
generated files, libraries, resources, and runtime assumptions are present.

Better choices:

1. Avoid native UI changes for now.
2. Put personal buttons/actions in The Pond web UI instead.
3. Use an existing param or existing settings surface when possible.
4. If native UI is truly required, build a complete matching prebuilt release
   from one source commit, not a one-file UI binary transplant.

Ubuntu / WSL recommendation
---------------------------
Ubuntu will help, but it is not a magic fix for comma-ready binaries.

What Ubuntu/WSL is good for:

- Searching and reading code in a Linux-like environment.
- Running source-tree setup scripts such as `tools/ubuntu_setup.sh`.
- Running `uv sync`, Python checks, tests, and linters.
- Building local developer targets to catch compile errors earlier.
- Understanding the full build process before touching the comma.

What normal Ubuntu/WSL on an Intel/AMD PC does not automatically do:

- It does not automatically produce a comma-ready ARM64/TICI `selfdrive/ui/ui`
  binary.
- Cross-compiling or emulating ARM64 is a separate project.
- A binary built for the laptop cannot simply be copied to the comma.

Practical use of Ubuntu next time:

1. Use Ubuntu/WSL to set up the full source checkout cleanly.
2. Run source checks and targeted builds to confirm the code is internally
   consistent.
3. Use it to understand which artifacts a proper prebuilt release needs.
4. Only after that decide whether the final ARM64 build should happen on the
   comma, through a proper release workflow, or not at all.

Safer place for the Navigation Assist test action
-------------------------------------------------
If the goal is just to have a personal button that triggers a test action, put
it in The Pond web UI instead of the native settings screen.

Reason:

- The Pond is Python/static web code.
- It does not require rebuilding `selfdrive/ui/ui`.
- It can call backend endpoints, set params, trigger diagnostics, or run safe
  personal actions.
- It is much less likely to create a boot-logo hang.

Rules for future changes
------------------------
1. One purpose per branch.
2. One behavior change per commit when possible.
3. Keep a known-good install branch untouched.
4. Do not add new persistent params to a prebuilt branch unless the matching
   compiled params extension is rebuilt.
5. Do not copy one native executable across branch families as a shortcut.
6. For assets and sounds, direct prebuilt-branch changes are usually fine.
7. For C++ UI, schemas, DBC generator changes, and compiled extensions, start
   in the source branch and plan the full build/release path.
8. Before driving, verify the comma boots cleanly, manager processes are
   healthy, and the branch/commit are the expected ones.
